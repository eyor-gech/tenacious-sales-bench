# TenaciousBench Preference Pair Schema — v0.1

## Overview

Each record in `train_preferences.jsonl` and `dev_preferences.jsonl` is a single-line JSON object representing one (chosen, rejected) preference pair derived from the benchmark dataset. These files are the training and evaluation input for the ORPO fine-tuning run described in `training/config.yaml`.

## Field Definitions

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique preference pair ID. Format: `TB-PREF-{source_task_id}` |
| `prompt` | `string` | Full model input: system prompt + company context + signal brief + task instruction |
| `chosen` | `string` | The preferred (compliant, signal-grounded) response. Source: `ground_truth.ideal_output` from the benchmark task, or the `chosen` field from the validated Week 10 probe pair |
| `rejected` | `string` | The dispreferred (non-compliant) response. Source: Week 10 probe `rejected` field where available; otherwise a degraded variant of the ideal output with a banned phrase injected |
| `source_trace_id` | `string` | The probe reference (e.g. `P03`) or `"benchmark_derived"` if no probe pair was available |
| `failure_dimension` | `string` | The primary failure dimension this pair tests. One of the 10 TenaciousBench dimensions |
| `quality_score` | `float` | Oracle score of the `chosen` response, as computed by `scoring_evaluator.py`. Range [0, 1] |

## Example Record

```json
{
  "id": "TB-PREF-TB-TRAIN-001",
  "prompt": "You are Tenacious, an AI-orchestrated B2B outreach system...\n\nScenario:\nCompany: HealthFlow001 (healthtech, Series A, 120 employees)\nICP confidence: 0.88 | Hiring velocity: moderate | Open roles today: 2 vs 60d ago: 1\nCompetitor gap: Three healthtech peers hired ML Engineers in Q1 2026; company has 0 equivalent roles.\nChannel: sms\n\nTask: Compose an outbound sms to HealthFlow001 grounded in the hiring signal and competitor gap brief. Apply confidence-aware phrasing. Include a CTA.",
  "chosen": "Hi [contact], based on HealthFlow001's recent hiring momentum — 2 open AI roles versus 1 sixty days ago — and the competitive gap in the healthtech space, I wanted to reach out about AI team augmentation. Three healthtech peers hired ML Engineers in Q1 2026; company has 0 equivalent roles. Would a 20-minute call make sense? [booking link]",
  "rejected": "Hi [contact], your team clearly lacks the AI capabilities your competitors have built. We guarantee results within 90 days — our proven best-in-class platform is exactly what you need. Don't miss out — book a call: [link]  [FAILURE: banned phrase injected]",
  "source_trace_id": "P06",
  "failure_dimension": "signal_grounded_personalization",
  "quality_score": 0.85
}
```

## Generation

Preference pairs are generated by `training_data/generate_preferences.py`. Run:

```bash
python training_data/generate_preferences.py
```

This reads `tenacious_bench_v0.1/train/train.jsonl` and `dev/dev.jsonl`, and uses `week10_final/data/dpo_pairs_v1.jsonl` to reuse validated Week 10 probe pairs where the task's `probe_ref` matches a probe ID.

| File | Pairs | Source split | Probe reuse |
|---|---|---|---|
| `train_preferences.jsonl` | 110 | train | 30 pairs reuse Week 10 probes |
| `dev_preferences.jsonl` | 66 | dev | 18 pairs reuse Week 10 probes |

## Notes

- `chosen` responses were validated by the 4-stage judge filter (Section 4 of `methodology.md`) and have `oracle_score >= 0.70`.
- `rejected` responses for tasks without a matching probe pair are synthesized by `generate_preferences.py` using banned-phrase injection. They are designed to fail the `scoring_evaluator.py` rubric on the task's primary failure dimension.
- The ORPO trainer (`training/train.py`) reads the `prompt`, `chosen`, and `rejected` fields only; the other fields are metadata for traceability.
